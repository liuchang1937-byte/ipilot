1. Function Calling 是什么？
Function Calling 是模型根据用户意图和工具 Schema 生成结构化调用请求的能力。模型只负责选择工具并给出参数，宿主程序负责校验、鉴权、真实执行，再把结果返回模型生成最终回答；它不是模型直接执行函数，也不能替代超时、重试、幂等和安全控制。[1]

从原理和流程看，开发者提供工具的名称、描述与参数约束，即工具 Schema；模型根据用户意图生成工具名和参数；宿主程序在真实执行前进行确定性检查，包括校验、鉴权和业务条件检查，然后把工具结果作为工具消息回传模型，由模型生成最终回答。JSON 格式正确也不代表订单号、权限或业务条件正确，因此不能直接运行模型生成的任意代码。[1] 例如用户要查询订单物流，模型可以输出查询工具名和订单号，服务端校验身份并查询，最后把物流结果回传模型；模型可能直接回答，也可能连续调用多个工具，所以不一定固定两次模型请求。[1]

Function Calling 与 MCP、Skill 处于不同层次：Function Calling 是模型表达“调用哪个工具及参数”的交互能力；MCP 是宿主连接外部工具和资源的标准协议，应用可以把 MCP 发现的工具转换成模型可理解的工具 Schema，再由 Function Calling 选择。[2] Skill 则是指导 Agent 组合能力完成任务的知识与流程。可以理解为 Function Calling 提供调用语言，MCP 提供标准化能力接口，Skill 提供如何完成任务的方法，但三者仍需权限、执行器和状态管理配合。[3]

完整链路可以包括：Client 从 Server 发现工具，Host 将描述转换成模型工具定义，模型生成调用意图，Host 校验后通过 Client 发请求，Server 执行并返回结果，Host 再向模型反馈。[2] Function Calling 可以调用普通本地函数，MCP 也可被确定性的应用直接调用，所以协议本身并不依赖某个模型 API。[2]
