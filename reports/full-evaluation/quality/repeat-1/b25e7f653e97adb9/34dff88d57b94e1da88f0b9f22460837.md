MCP 把消息语义和传输方式分开：无论本地还是远程，消息层都采用 JSON-RPC 2.0，传输方式只决定这些 JSON-RPC 消息如何到达对端 [1]。

- 本地进程（本地 MCP Server）：常通过 stdio 传输。Client 把 Server 作为子进程启动，使用标准输入/输出传递协议消息；这种方式延迟低、无需开放端口。普通日志应写到 stderr，避免污染消息流 [1]。
- 远程服务：推荐使用 Streamable HTTP。它用 HTTP 请求传递消息，并可通过 SSE 推送多个事件；并非所有响应都必须保持一个长连接。它便于多个 Client 共享和集中管理 [1]。
- 旧方案：早期 HTTP+SSE 双端点方案已不再是新项目的首选；2025-11-25 版规范列出 stdio 和 Streamable HTTP 两种标准传输，旧 HTTP+SSE 应按兼容需求处理 [1]。

从角色上看，Host 内的 Client 维护到某个 Server 的协议会话，Server 暴露 Tools、Resources、Prompts 等能力，底层通过支持的传输交换 JSON-RPC 消息 [3]。此外，客户端还需管理连接生命周期、会话和取消；重连不会自动保证外部操作只执行一次 [1]。
