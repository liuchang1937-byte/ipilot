1. 模型网关提供哪些治理能力？
模型网关（LLM网关）作为业务与模型供应商之间的统一层，主要提供以下治理能力：统一接口、鉴权、模型路由、限流、配额、重试、熔断、缓存、成本统计和观测，并可进行敏感信息过滤[1]。实践中，它可统一记录费用、设置团队配额，并在可恢复故障时执行受控降级[1]。缓存治理需让缓存键包含模型、参数、上下文和权限范围，避免不同用户的私有回答混用；流式响应中途失败也不能简单重试后拼接重复内容，需要明确部分输出与恢复策略[1]。职责边界上，网关不应承担具体业务 Prompt 和 Agent 状态，否则会形成难维护的中心化逻辑[1]。

2. 助手连接数据库时如何限制权限？
限制助手连接数据库的权限，核心是最小权限和受控访问：不要把数据库高权限凭据直接交给模型，而应通过受控数据访问层仅暴露允许的表、字段和查询模板，默认只读并实施行列级权限[4]。生成 SQL 后先做 AST 检查、参数化、成本预估和敏感字段拦截，再在限时限量的隔离账号中执行；结果按用户权限脱敏并记录审计日志[4]。回答必须引用真实查询结果和执行 ID，查询失败或空结果时不得自行补全[4]。身份和租户范围应来自可信登录态，不由模型从用户文字中自行决定[4]。能提供固定业务接口时，就不暴露任意 SQL；例如查订单场景可优先走固定业务接口；必须生成 SQL 时要解析语法树，限制表、列、函数、语句类型和结果规模[4]。参数化查询主要防止值注入，不能替代授权和逻辑检查；查询返回前做字段裁剪与脱敏，写操作使用独立权限、事务和审计，并校验指标口径及时间范围[4]。
