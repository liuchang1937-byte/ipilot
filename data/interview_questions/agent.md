# Agent 面试题

> 题目参考[小林面试笔记](https://xiaolinnote.com/ai/)；答案以自己的表述整理并补充原理、例子和工程边界。
> 参考答案用于理解与复盘，评分应关注核心概念与逻辑，不要求逐字背诵或覆盖所有扩展细节。

## A001｜什么是 Agent？与大模型有什么本质不同？

- 知识点：Agent基础
- 难度：基础
- 标签：Agent 定义、LLM 应用、自主决策
- 考察方向：候选人能否从目标、状态、行动、反馈闭环等角度定义 Agent。
- 参考答案：大模型本质上是根据上下文生成输出的概率模型，本身不负责持续维护任务状态或真实执行动作。Agent 是以 LLM 为推理核心、以目标为驱动的运行系统，它会感知当前状态，规划下一步，调用工具影响外部环境，读取执行结果并继续决策，直到完成目标或触发停止条件。两者的核心差异是：LLM 提供认知能力，Agent 在其外部增加状态、工具、控制循环、记忆和反馈闭环。例如，一个资料调研 Agent 会先确定检索范围，调用搜索工具，检查是否获得足够证据，再组织结论；如果资料不足，就调整查询继续检索。控制循环通常由宿主代码驱动，模型输出的是行动建议，外部操作仍由程序执行。判断是否具备 Agent 特征，要看是否能依据观察更新决策，而不是仅仅看界面能否聊天或是否注册了工具。自主性也应受权限、预算和验收条件约束。
- 评分要点：区分“模型”与“系统”；提到目标、状态、工具和反馈循环；说明 Agent 不等于简单聊天封装。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/agent/1_whatisagent.html)

## A002｜Agent 的基本架构由哪些核心组件构成？

- 知识点：Agent架构
- 难度：基础
- 标签：架构、规划、工具、记忆
- 考察方向：核心组件及一次任务从输入到完成的调用链。
- 参考答案：Agent的四个核心组件是LLM、工具、记忆和规划模块。LLM负责理解任务与决策；工具负责搜索、执行代码或调用API，使Agent能够作用于外部环境；记忆保存对话和任务状态；规划模块把复杂目标拆成可执行步骤。System Prompt、权限、日志和容错属于这些核心组件之外的重要工程支撑。一次运行的数据流可以概括为：用户目标进入规划模块，规划结果与已有状态组成模型上下文，模型选择工具，执行器校验参数并运行，结果写回状态和记忆，模型再判断是否继续。记忆不能只保存聊天文本，还要保存已完成步骤、待办和工具回执。真正把组件串起来的是运行时控制器，它负责停止条件、异常处理和检查点，避免模型输出了计划却没有执行。
- 评分要点：至少覆盖模型、规划、工具、记忆和运行循环；能说清模块之间的数据流。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/agent/2_components.html)

## A003｜Workflow，Agent，Tools 这三个的概念和区别介绍一下？

- 知识点：Workflow选型
- 难度：基础
- 标签：Workflow、工具调用、Agent
- 考察方向：确定性编排与模型自主决策之间的边界。
- 参考答案：Tool 是一个边界清晰、可调用的外部能力，如查询数据库或发送邮件；Workflow 是预先定义好的步骤、分支和依赖，执行路径主要由代码决定；Agent 则依据目标和运行时反馈动态决定下一步做什么、调用哪个工具以及何时结束。三者可以组合：Workflow 控制关键流程，Agent 处理开放决策，Tool 提供实际执行能力。例如，报销系统中的金额校验是 Tool，固定的提交、审核、付款流程是 Workflow，自动分析异常票据并决定补查哪些资料的部分可以是 Agent。Workflow 的节点既可以是普通函数，也可以是一次模型调用或一个 Agent；Agent 也能调用固定子流程。因此三者不是互斥产品，更不能简单理解成工具数量增加后就自动变成 Agent。选型应看哪些步骤需要确定性，哪些决策需要运行时探索。
- 评分要点：说清能力、流程和决策三个层级；避免把 Tool Calling 直接等同于 Agent。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/agent/3_workflow_tools.html)

## A004｜了解哪些其他的 Agent 设计范式？Agent 和 Workflow 的区别是什么？

- 知识点：Agent架构选型
- 难度：中等
- 标签：架构选型、确定性、成本
- 考察方向：能否结合可预测性、失败成本和任务开放程度进行选型。
- 参考答案：常见范式包括 ReAct、Plan-and-Execute、Reflection、Router、Supervisor、并行多 Agent 和黑板协作等。Workflow 的节点和转移条件通常预先确定，优点是稳定、可测试；Agent 的路径由模型结合环境动态选择，适合目标明确但步骤未知的任务。实际工程常采用混合设计：高风险步骤使用 Workflow 固化，信息收集和方案探索交给 Agent。这些概念也不全在同一层级：ReAct 和 Plan-and-Execute 描述执行与决策的组织方式，Reflection 是可叠加的检查机制，Supervisor 则更多描述多个执行者的调度架构。例如，退款的身份核验与额度判断适合固定流程，定位复杂故障可能需要动态调查。即使采用 Agent，也能用状态机限制合法转移，所以动态决策不等于完全放任模型控制。
- 评分要点：说明 Workflow 与 Agent 的决策边界；比较 ReAct、规划执行与反思；认识不同架构层级与混合使用。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/agent/4_patterns.html)

## A005｜Agent 推理模式有哪些？ReAct 是啥？具体是怎么实现的？

- 知识点：ReAct
- 难度：中等
- 标签：ReAct、状态机、推理循环
- 考察方向：Thought/Action/Observation 循环及其可执行实现。
- 参考答案：常见推理模式包括直接回答、CoT和ReAct。直接回答没有显式中间过程；CoT让模型先组织多步推理再给结论；ReAct进一步把推理与行动交替进行，形成Thought—Action—Observation循环：模型决定工具及参数，宿主执行后把观察结果送回模型，直到满足结束条件。工程实现还要限制步数、预算和重复调用。代码层面可以实现一个有界循环：构建消息，调用模型，判断返回的是最终答案还是工具请求；若是工具请求，就检查工具名、参数和权限，执行后追加工具结果，再进入下一轮。工具报错应作为明确观察反馈，不能直接吞掉。ReAct 的关键是行动改变了下一次决策所依据的信息，不是强制打印完整思维过程；日志可以保存动作、观察和简短决策依据，而不依赖模型内部推理文本。
- 评分要点：完整说明 Action—Observation反馈；提到工具执行由宿主完成；具备停止与容错意识。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/agent/5_react.html)

## A006｜ReAct、Plan-and-Execute、Reflection 三种范式有什么核心区别？实际项目中该如何选型？

- 知识点：规划策略
- 难度：中等
- 标签：Plan-and-Execute、Reflection、ReAct
- 考察方向：三类范式的准确性、延迟、成本和恢复能力差异。
- 参考答案：ReAct 边思考边行动，适合信息逐步显现、需要频繁工具交互的任务，但调用轮次多；Plan-and-Execute 先生成整体计划再逐项执行，适合依赖关系清楚的长任务，但初始计划错误会向后传播；Reflection 在结果或阶段完成后检查缺陷并修正，适合质量要求高、允许增加成本的任务。选型要结合任务开放度、可逆性、延迟预算和失败代价，复杂项目常把三者组合使用。例如，开放式故障调查适合根据日志逐步选择工具；生成研究报告可以先列出资料搜集、比较和写作步骤，再由执行器完成；报告完成后则可检查论据缺失和结论冲突。Reflection 应有具体标准和外部证据，而不是让同一个模型无限重写。计划遇到新信息也需要修订，并非提前规划后就禁止变化；三种机制都应有步数、费用和时间上限。
- 评分要点：比较三者控制时机和代价；给出基于场景的选择依据。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/agent/6_three_patterns.html)

## A007｜复杂任务怎么做的任务拆分？为什么要拆分？效果如何提升？

- 知识点：任务分解
- 难度：中等
- 标签：任务分解、依赖图、验收条件
- 考察方向：子任务边界、依赖关系、完成判据与动态重规划。
- 参考答案：先把目标转为可验证的交付物，再按信息依赖、工具边界或专业领域拆成子任务，并为每个子任务定义输入、输出、前置条件和验收标准。拆分可以缩短单步上下文、提高可观测性、支持并行和失败重试。效果提升依靠依赖图、关键路径优先、子任务粒度约束、执行后校验以及根据新信息动态重规划；拆得过细会增加通信成本。以技术调研为例，可拆成明确范围、并行搜集多个方案、统一指标对比、形成建议四部分，最后一部分依赖前面的证据。独立检索可并行，依赖同一业务状态的写入不能随意并行。每步返回结构化产物，使失败可以定位到局部并单独重试。是否改善效果，应比较任务成功率、返工率、总耗时与调用费用，不能把拆分后的局部准确率直接当成整体收益。
- 评分要点：强调可验证输出和依赖；说明收益与过度拆分的代价。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/agent/7_tasksplit.html)

## A008｜请你介绍一下 AI Agent 的记忆机制，并说明在实际开发中应该如何设计记忆模块？

- 知识点：Agent记忆
- 难度：中等
- 标签：记忆、状态、知识库
- 考察方向：不同记忆类型的职责、生命周期和访问方式。
- 参考答案：题解可将Agent记忆分为四层：感知记忆保存当前原始输入，短期记忆位于上下文窗口并服务当前任务，长期记忆存入外部数据库并通过语义检索召回，实体记忆则结构化保存人物、对象和关键事实。实际设计要回答“存什么、怎么存、何时取”，并根据类型选择主动注入或按需检索，同时处理去重、过期、权限和删除。这是一种便于解释的分类，并非所有框架统一采用的标准。短期记忆应包含目标、近期消息和未决动作；长期记忆应保存跨会话有用且经过确认的信息；实体记忆适合记录对象属性与关系，避免姓名、日期和约束被摘要误改。写入时保留来源、时间和可信度，检索时先按用户与权限过滤。不是所有工具日志都值得长期保存，也不能把模型猜测直接当成事实写入。
- 评分要点：给出记忆分类；覆盖写入、检索、更新、遗忘和隐私。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/agent/8_memory.html)

## A009｜Agent 的长短期记忆系统怎么做的？记忆是怎么存的？粒度是多少？怎么用的？

- 知识点：长期记忆
- 前置知识：Agent记忆
- 难度：进阶
- 标签：长期记忆、去重、遗忘策略
- 考察方向：记忆抽取、重要性评分、冲突处理、过期与压缩。
- 参考答案：短期记忆通常就是上下文窗口中的对话与当前任务中间状态，任务结束后可释放；长期记忆把可复用信息Embedding后存入向量数据库，使用时做语义检索并注入Prompt。粒度可按一次完整交互或一个关键事件保存：太细会增加噪声，太粗会损失细节。写入前还应按重要性、新颖性和可信度筛选，避免永久保存错误结论。例如，当前订单号、已确认退款金额和待执行步骤适合结构化状态；近期问答可保存为消息列表；产品知识可以按主题片段建立向量索引。粒度应围绕可独立复用的事实或事件，不是机械地一轮对话存一条向量。读取时先判断当前任务需要哪些记忆，再执行过滤、召回和排序，将少量相关内容注入上下文。用户纠错后要更新或废弃旧记录，并保留必要的版本关系。
- 评分要点：明确存储介质不是核心，关键是粒度、生命周期与读写策略。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/agent/9_memory_storage.html)

## A010｜什么是 Multi-Agent？

- 知识点：多Agent协作
- 难度：中等
- 标签：Multi-Agent、职责拆分、复杂任务
- 考察方向：专业能力、上下文隔离、并行性与治理成本之间的权衡。
- 参考答案：Multi-Agent是多个具有不同分工的Agent协作完成任务，例如搜索、编码和评审分别由专业Agent承担。它主要缓解单Agent的上下文窗口限制和单点能力限制，并可通过并行执行缩短长任务时间。代价是通信、状态一致性、重复劳动和故障治理更复杂，因此只有专业分工或并行收益明显时才值得使用。例如，一个执行者负责查资料，一个负责验证结论，一个负责整理报告，协调器统一维护目标与交付状态。这里的多个 Agent 不一定使用不同模型，区别在于角色、工具权限、上下文和职责。多 Agent 有利于隔离复杂子任务和独立检查，但增加了交接、重复调用与一致性成本；如果只是同一个模型连续改写几遍文本，却没有角色边界和协作状态，就不能说明系统设计得更好。
- 评分要点：提到独立角色与协作机制；同时说明收益和治理成本。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/agent/10_multiagent.html)

## A011｜说说 Single-Agent 和 Multi-Agent 的设计方案？

- 知识点：多Agent协作
- 前置知识：多Agent协作
- 难度：进阶
- 标签：Multi-Agent、角色设计、协调
- 考察方向：角色边界、输入输出契约、调度者和共享状态。
- 参考答案：Single-Agent 由一个决策核心访问多种工具，状态集中、调试简单，适合中小型任务。Multi-Agent 将任务按领域、权限或上下文拆给多个 Agent，可由 Supervisor 统一调度，也可通过消息或共享状态协作，适合可并行且专业差异明显的任务。选型时先验证单 Agent 是否已足够，只有上下文膨胀、权限隔离或专业并行收益明显时再拆分。Single-Agent 通常由一个循环维护任务状态并选择工具，结构简单，调试和归因较容易。Multi-Agent 可以采用主管分发、流水线交接或并行专家汇总，但必须定义输入输出契约和结果合并规则。应在工具权限需要隔离、上下文相互干扰或子任务可独立并行时考虑拆分，而不是只看问题文字是否复杂。先建立单 Agent 基线，再用相同测试集证明成功率或延迟收益足以抵消协作成本。
- 评分要点：描述两种架构；给出选择条件而非只列优缺点。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/agent/11_single_multi.html)

## A012｜Agent 记忆压缩通常有哪些方法？

- 知识点：上下文压缩
- 难度：进阶
- 标签：上下文压缩、摘要、记忆
- 考察方向：滑动窗口、结构化摘要、关键事件保留与可追溯性。
- 参考答案：常见方法有滑动窗口、递归摘要、结构化状态抽取、按重要性保留、相似消息聚类去重、旧消息外置后按需检索，以及只保留决策、证据和未完成事项。压缩结果应带原始消息引用，关键约束和工具结果不能只靠自由文本摘要。最好通过“压缩后能否继续完成任务”的回归集评估信息损失。具体可组合滑动窗口、阶段摘要、结构化事实提取、语义检索与冗余工具输出裁剪。压缩时应把用户确认的硬约束、关键决策和未完成步骤单独保存，近期原话保持较高保真度，历史细节按需取回。摘要要保留证据指针，不能把不确定信息压缩成确定事实。验证时可以检查目标、对象和约束在多轮后是否仍一致，以及恢复任务时是否丢失重要操作回执。
- 评分要点：至少三种方法；强调关键事实、可追溯和评测。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/agent/12_memcompress.html)

## A013｜在工程实践中，为什么有时候选择「手搓」Agent，而不是直接用成熟框架？

- 知识点：框架选型
- 难度：中等
- 标签：框架选型、可控性、可观测性
- 考察方向：定制需求、依赖复杂度、调试能力和迁移成本。
- 参考答案：当流程较小但对状态、延迟、权限、日志或故障恢复有强定制要求时，自行实现循环往往更透明，也能减少框架抽象和版本依赖。成熟框架适合快速搭建、通用集成和复杂编排，但可能带来隐式行为、调试困难和升级成本。手搓并非从零造所有组件，而是保留核心控制权，同时复用模型客户端、追踪和存储等成熟基础设施。例如，业务只需要少量工具，但要求每一步精确记录状态、限制权限并支持断点恢复时，直接实现调用循环可能更容易调试。手写并不意味着重造模型客户端、数据库和监控系统，可以复用成熟基础设施，只掌握关键控制逻辑。相应代价是自己维护消息格式、异常分支、兼容性与测试。回答应比较团队经验和长期维护成本；当流程复杂或框架能力已经满足需求时，使用框架往往更合适。
- 评分要点：结合业务约束比较可控性、可观测性与维护成本；说明复用基础设施；不把手写或框架视为绝对更优。

## A023｜Agent 的「任务幻觉」是什么？如何避免没有执行工具却声称任务已经完成？

- 难度：进阶

## A024｜大模型或 Agent 连接数据库时，如何防止越权、敏感数据泄漏和查询幻觉？

- 知识点：数据库工具安全
- 难度：进阶
- 标签：数据库安全、权限、审计
- 考察方向：最小权限、查询白名单、脱敏、只读代理和结果验证。
- 参考答案：不要把数据库高权限凭据直接交给模型，应通过受控数据访问层暴露允许的表、字段和查询模板，默认只读并实施行列级权限。生成SQL后先做AST检查、参数化、成本预估和敏感字段拦截，再在限时限量的隔离账号中执行；结果按用户权限脱敏并记录审计日志。回答必须引用真实查询结果和执行ID，查询失败或空结果时不得自行补全。身份和租户范围应来自可信登录态，不由模型从用户文字中自行决定。能提供查订单等固定业务接口时，就不暴露任意 SQL；必须生成 SQL 时要解析语法树，限制表、列、函数、语句类型和结果规模。参数化查询主要防止值注入，不能替代授权和逻辑检查。查询返回前做字段裁剪与脱敏，写操作使用独立权限、事务和审计，并校验指标口径及时间范围，兼顾查询安全和答案正确性。
