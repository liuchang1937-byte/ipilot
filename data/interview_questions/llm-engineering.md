# 大模型工程面试题

> 题目参考[小林面试笔记](https://xiaolinnote.com/ai/)；答案以自己的表述整理并补充原理、例子和工程边界。
> 参考答案用于理解与复盘，评分应关注核心概念与逻辑，不要求逐字背诵或覆盖所有扩展细节。

## L001｜什么是大语言模型？和传统 NLP 模型有什么区别？

- 知识点：LLM基础
- 难度：基础
- 参考答案：大语言模型是在海量语料上通过自监督目标训练的通用生成模型，通常以Transformer为核心，通过上下文预测下一个Token。传统NLP常针对分类、序列标注等单任务设计并使用专门标注数据。LLM可通过提示和上下文学习统一处理多任务，但参数、推理成本、幻觉和不可解释性也更突出。例如，传统情感分类器通常输出正负标签，而生成式 LLM 可以根据指令解释原因、改写内容或总结文章，利用同一预训练模型处理不同任务。但传统 NLP 也包含生成模型，大模型也不是只能做聊天，因此差异不能简单概括为标签对文本。当前常见生成式 LLM 使用自回归目标，通过上下文适应任务；它的输出是统计预测，不等于实时查阅事实库，也不保证理解与推理永远正确。
- 评分要点：预训练目标、通用性、上下文学习及工程代价。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/what_is_llm.html)

## L002｜讲讲 Transformer 架构基本原理？Encoder 和 Decoder 是什么？

- 知识点：Transformer
- 难度：中等
- 参考答案：Transformer由多层注意力、前馈网络、残差连接和归一化组成。Encoder对输入做双向表示，Decoder通过掩码自注意力自回归生成，并可用交叉注意力读取Encoder输出。仅Encoder适合理解任务，仅Decoder是多数生成式LLM的选择，Encoder-Decoder适合输入到输出的条件生成。Self-Attention 将输入映射成 Q、K、V，通过 Q 与 K 的匹配权重聚合 V，再配合前馈网络、残差和归一化更新表示。Encoder 通常读取双向上下文，Decoder 的自注意力用因果遮罩限制未来信息；原始 Encoder-Decoder 还通过交叉注意力读取编码结果。训练时可并行处理已知序列，推理生成仍逐 Token 进行。注意力改善长距离信息连接，却有计算与显存成本，不能理解为所有阶段都完全并行。
- 评分要点：注意力与FFN；三种架构及掩码/交叉注意力。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/transformer_architecture.html)

## L003｜多头注意力（MHA）有哪些局限？MQA、GQA、Flash Attention 怎么解决？

- 知识点：注意力优化
- 前置知识：Transformer
- 难度：进阶
- 参考答案：MHA 中每个查询头有独立的 K/V 头，长序列下 KV Cache 与显存带宽开销较大；稠密注意力还需要比较序列中的大量位置，计算量通常随长度平方增长。MQA 让所有查询头共享一组 K/V，GQA 则把查询头分组，每组共享 K/V，以减少缓存和访存，在速度、显存与表达能力间折中。FlashAttention 从实现层优化：通过分块与在线 Softmax，避免把完整注意力矩阵反复写入显存，从而降低 IO 与中间存储，仍计算精确注意力。它通常不将理论二次计算复杂度改成线性，也不改变查询头与 K/V 的共享方式。因此 GQA 可以与 FlashAttention 一起使用；实际收益需要在目标模型、序列长度、并发和硬件上测试，而不是只比较算法名称。
- 评分要点：区分 MQA/GQA 的 K/V 共享与 FlashAttention 的 IO 优化；不把精确稠密注意力说成线性计算。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/mha_mqa_gqa_flash_attention.html)

## L004｜大模型的位置编码是干什么用的？sin/cos、RoPE、ALiBi 有什么区别？

- 知识点：位置编码
- 前置知识：Transformer
- 难度：中等
- 参考答案：自注意力本身对顺序不敏感，因此需要位置编码。sin/cos把绝对位置向量加入表示，可一定程度外推；RoPE通过旋转Q/K把相对位置信息编码进注意力内积，是当前常用方案；ALiBi直接给注意力分数加入与距离相关的线性偏置，简单且具备长度外推特性。三者在实现、相对位置表达和长上下文表现上不同。如果没有位置信息，注意力难以区分同一组词的不同顺序。sin/cos 使用固定频率的位置向量，RoPE 对 Q/K 做与位置有关的旋转，使点积体现相对位置关系，ALiBi 则在注意力分数中加入与距离相关的偏置。它们影响长度泛化，但支持更长窗口还与训练长度、缩放方案和任务有关。不能仅因使用 RoPE 就保证超出训练长度后仍准确，应该测不同位置和跨段依赖任务。
- 评分要点：为何需要位置；三种方案的作用位置与特点。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/position_encoding.html)

## L005｜什么是大模型项目的分词器？原理是什么？

- 知识点：Tokenizer
- 难度：中等
- 参考答案：Tokenizer将字符串转换为有限词表中的Token ID，模型只处理这些ID。常见BPE、WordPiece或Unigram从字符/字节出发学习高频子词组合，并保留特殊Token。词表和算法影响多语言压缩率、代码表示、未知字符、上下文占用与计费；解码时再把Token序列还原为文本。Token 不等同于汉字、单词或字符，一个词可能被拆成多个子词，字节级方案也能表示少见字符串。词表学习在压缩效率、覆盖范围和序列长度之间折中；推理时按既定规则编码，再将模型输出 ID 解码。领域术语拆得过碎会增加长度与费用，代码和多语言尤其需要评估。估算上下文时应使用对应模型的 tokenizer，不能默认所有模型共用固定的字数换算比例。
- 评分要点：文本到ID、子词算法、词表训练及业务影响。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/tokenizer.html)

## L006｜大模型是怎么训练出来的？

- 知识点：模型训练
- 难度：中等
- 参考答案：可以按数据准备、预训练、后训练和验证四部分展开。首先收集、清洗和去重语料，控制领域与语言配比，处理测试污染，再确定分词器与模型配置。预训练通过预测 Token 等自监督目标学习语言模式和知识，工程上依靠分布式并行、混合精度、优化器和检查点，兼顾计算效率与故障恢复。后训练中的 SFT 用高质量示范教模型遵循指令；偏好优化或强化训练则利用人类偏好、奖励模型或可验证反馈改善回答与任务表现。阶段不一定严格固定，SFT 本身也属于后训练，部分模型会穿插数据筛选、继续预训练和强化优化。最后使用独立能力集、业务任务、安全测试和部署压测验证质量。回答不应只列方法名，还要说明每阶段解决什么问题；数据质量差或奖励定义错误时，增加训练步骤并不保证效果提升。
- 评分要点：数据、预训练、后训练、评测和分布式工程。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/llm_training.html)

## L007｜什么是 Scaling Law？大模型的「涌现能力」是怎么回事？

- 知识点：Scaling Law
- 难度：进阶
- 参考答案：Scaling Law描述模型参数、训练数据、计算量与损失之间近似幂律关系，可用于分配训练预算，但前提是数据质量和训练方式相近。所谓涌现是某些能力在规模提高后指标看似突然出现，部分来自能力真实提升，部分也可能由离散评测阈值造成。规模并不保证特定业务效果，仍需任务评测。它用于给定训练设置下估算参数、数据与计算的收益，帮助安排计算预算，而不是保证无限扩大会永远按相同比例进步。计算最优和部署总成本最优也可能不同，因为小模型多训练一些可能更省长期推理费用。所谓涌现是某些能力随规模表现出明显变化，但阈值也可能受离散评分方式影响；应同时观察连续指标与业务表现，不能把某条参数数据比例当成所有模型的通用常数。
- 评分要点：幂律关系、算力最优配比、涌现解释和边界。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/scaling_law_emergence.html)

## L008｜大模型微调的方案有哪些？

- 知识点：微调
- 难度：中等
- 参考答案：微调通常不是第一选择，应先尝试Prompt、Few-shot或RAG。真正需要稳定输出特定风格、格式，或希望用小模型替代昂贵模型时再考虑。方案包括全量微调、Adapter、Prefix/Prompt Tuning、LoRA和QLoRA；资源有限时LoRA/QLoRA最常用。SFT负责指令行为，有偏好对齐需求时还可使用DPO等方法，最终按数据、硬件和部署目标选型。全量微调更新大部分权重，容量较大但显存和优化器状态开销高；PEFT 只更新少量新增或选定参数，适合资源受限场景。QLoRA 将基座权重低比特存储，同时训练低秩适配器，不等于所有训练计算都用四位精度。SFT 是训练目标与数据形式，LoRA 是参数更新方式，两者可结合。是否值得微调还要比较数据准备、回归风险与维护成本，动态事实通常继续通过检索提供。
- 评分要点：列举全量与多种PEFT；能说明场景取舍。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/finetuning.html)

## L009｜请讲一下 LoRA 技术，除了减少参数量，它还有哪些优点？

- 知识点：LoRA
- 前置知识：微调
- 难度：进阶
- 参考答案：LoRA冻结原权重，用两个低秩矩阵近似权重更新，并把更新注入注意力或其他线性层。除减少训练参数和显存外，它便于为多个任务保存小型适配器、快速切换或组合，也可在部署前合并进基础权重而不增加推理层。秩、目标模块和数据质量仍会影响容量与效果。若原矩阵为 W，训练的增量可以写成 ΔW=BA，秩 r 远小于原维度，再按缩放系数加回权重。训练时仍需要基座前向和反向相关计算，并非参数少就没有计算成本。合并适配器后通常可避免额外推理分支，未合并和多适配器服务的开销则要实测。冻结基座有助于控制更新范围，但不能保证没有遗忘或副作用；秩、目标层、数据与评测比单纯追求最低参数量更重要。
- 评分要点：低秩更新原理、多适配器、可合并及超参数权衡。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/lora.html)

## L010｜SFT 之后还有哪些 Post-Training？RLHF、DPO、GRPO、拒绝采样什么关系？

- 知识点：对齐训练
- 难度：进阶
- 参考答案：SFT后可用拒绝采样从多个候选中选优再训练；RLHF通常训练奖励模型并用PPO优化策略；DPO直接利用偏好对，省去显式奖励模型和在线强化学习；GRPO使用组内相对奖励估计优势，减少价值模型依赖。它们都利用偏好或奖励改善行为，但数据、在线采样、稳定性和成本不同。Post-Training 通常包含 SFT 及其后的优化，不应严格定义成仅 SFT 之后。拒绝采样可选出高质量候选再用于监督学习；DPO 用偏好对直接优化；PPO 和 GRPO 则属于强化优化方式，奖励可以来自模型、人类或可验证规则。GRPO 常以同一问题的一组输出构造相对优势，避免单独训练价值模型，但仍有采样与奖励成本。方法可以组合，关键是训练信号可靠以及收益能通过独立测试确认。
- 评分要点：说明 SFT 与后训练的关系；比较拒绝采样、PPO 式 RLHF、DPO 和 GRPO 的训练信号与成本。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/post_training.html)

## L011｜大模型的 DPO 和 PPO 的区别是什么？

- 知识点：偏好优化
- 前置知识：对齐训练
- 难度：进阶
- 参考答案：PPO式RLHF先训练奖励模型，再在线采样并通过策略梯度优化，同时用KL约束防止偏离参考模型，流程复杂但能直接优化奖励。DPO从偏好对推导出分类式目标，直接提高chosen相对rejected的概率，不需显式奖励模型，训练更稳定简单，但受离线偏好数据覆盖限制。标准 PPO 式 RLHF 常涉及策略、参考、奖励和价值估计，并通过在线采样适应当前策略的输出分布。标准 DPO 通常使用离线 chosen/rejected 数据与参考模型，训练流程较简单，但未覆盖的偏好场景仍可能失败。它不是只让模型模仿好答案，还会比较好坏答案相对参考策略的概率。两者并非对任意训练过程都等价，选择时应考虑奖励来源、在线采样条件、计算预算及数据质量。
- 评分要点：奖励模型、在线/离线、优化目标、稳定性与数据边界。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/dpo_vs_ppo.html)

## L012｜大模型生成文本时的解码策略有哪些？贪心、Beam Search、采样分别什么时候用？

- 知识点：解码策略
- 难度：中等
- 参考答案：贪心每步选择最高概率Token，速度快且稳定但容易局部最优；Beam Search保留多条高概率序列，适合翻译等更重整体概率的任务，但成本高且开放生成可能僵硬；采样按概率随机选择，可配合Temperature、Top-K和Top-P增加多样性，适合创作和对话。结构化任务通常偏确定性。贪心只做局部选择，Beam Search 保留有限数量的序列候选，也不保证找到真正的全局最优；它还可能偏好常见而缺乏多样性的表达。采样则从调整后的分布抽取 Token，用随机性换取多样性。结构化输出需要格式约束与校验，低随机性不能替代这些机制。即使使用贪心，相同请求在不同后端、数值计算或模型版本下也不一定逐字一致，应区分算法意图与工程可复现性。
- 评分要点：三者机制、成本、多样性和适用场景。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/decoding_strategies.html)

## L013｜大模型的参数：温度值、Top-P、Top-K 分别是什么？各个场景下的最佳设置是什么？

- 知识点：采样参数
- 前置知识：解码策略
- 难度：中等
- 参考答案：Temperature缩放Logits，越低分布越尖锐；Top-K只在概率最高的K个Token中采样；Top-P选择累计概率达到阈值的最小集合。事实问答和代码可用低温度，创作可提高温度并使用Top-P；不存在通用最佳值，应基于任务集评估，而且通常避免同时激进调整所有参数。温度常通过 logits 除以 T 后做 Softmax 改变分布，Top-K 固定候选数量，Top-P 根据累计概率动态决定候选集合。它们只改变采样行为，不能给模型补充知识或保证事实正确。实践应先固定模型版本和其他参数，再用业务集比较正确率、多样性、重复率与格式稳定性。不同 API 的参数范围和组合行为可能不同，因此不存在跨模型通用的最佳数值，温度为零也不等于结果一定可复现。
- 评分要点：参数机制准确；场景化而非给出绝对最佳值。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/temperature_top_p_top_k.html)

## L014｜KV Cache 是什么？Prompt Caching 的原理是什么？

- 知识点：KV Cache
- 前置知识：Transformer
- 难度：进阶
- 参考答案：自回归生成时，KV Cache保存已有Token各层的Key/Value，后续每步只计算新Token，降低重复计算但消耗显存。Prompt Caching复用相同或相同前缀Prompt的预填充结果，可跨请求减少首Token延迟和输入计算。前者主要服务单次生成过程，后者强调重复前缀复用，都要处理缓存键、失效和内存成本。prefill 先处理输入并生成各层 K/V，decode 为每个新 Token 计算新表示，并读取已有缓存，避免重算历史 K/V。缓存随序列长度、层数和 K/V 头数增长，也会限制高并发。跨请求复用通常要求前缀与模型配置兼容，生成式同义改写并不能保证命中；缓存复用也不同于直接返回过去的答案。应比较命中率、TTFT 和显存占用，权限隔离、失效与生命周期由具体服务实现。
- 评分要点：prefill/decode、单请求与跨请求、速度—显存权衡。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/kv_cache_prompt_caching.html)

## L015｜大模型量化是什么？INT8/INT4/AWQ/GPTQ 怎么选？

- 知识点：模型量化
- 难度：进阶
- 参考答案：量化用低比特表示权重或激活，以降低显存、带宽和计算成本，代价是精度风险。INT8通常损失小，INT4压缩更强；GPTQ利用校准数据做逐层训练后权重量化，通用性强；AWQ保护对输出敏感的重要权重，常有较好部署效果。选型需看硬件内核、模型大小、吞吐、延迟和业务精度实测。要区分权重量化、激活量化和 KV Cache 量化，以及只压缩存储和真实使用低比特内核计算。GPTQ 常用校准数据与误差近似逐层优化量化，AWQ 利用激活信息调整重要通道的缩放，减少关键权重的误差；不能把 AWQ 简化成始终保留一批 FP16 权重。四位模型未必在所有硬件都更快，需要核对算子支持，并在长文、代码和业务任务上验证精度、吞吐及尾部延迟。
- 评分要点：量化对象、比特权衡、AWQ/GPTQ思路及硬件适配。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/quantization.html)

## L016｜如何写好 Prompt？分享下 Prompt 工程实践经验？

- 知识点：Prompt工程
- 难度：中等
- 参考答案：先明确角色、目标、输入数据、约束、输出Schema和失败行为，再提供少量代表性示例。把可信指令与外部文本分隔，要求信息不足时拒答，并对结构化输出做程序校验。Prompt应版本化，在固定评测集上比较正确率、格式率、成本和稳定性，避免只凭几个示例调词。例如，要求系统从资料回答时，应明确哪些内容是证据、哪些是指令，以及证据不足如何处理；要求 JSON 时，应定义字段、类型和允许为空的条件。少量示例应包含正常、缺信息和异常输入，而不是只演示理想输出。改进 Prompt 要根据失败样本提出假设并做对照评测，记录模型版本和参数。提示能引导行为，但权限、业务规则和外部动作仍由代码强制执行。
- 评分要点：结构、边界、示例、校验、版本与评测。

## L017｜什么是 CoT？为啥效果好？它有什么缺点或局限性？

- 知识点：CoT
- 难度：中等
- 参考答案：CoT通过中间推理步骤分解复杂问题，使模型在数学、规划等任务中更容易保持局部一致。它可能增加Token、延迟和错误累积，也不保证推理真实可靠；完整内部推理还可能泄露敏感信息。工程上可要求简短依据或使用隐藏推理，只向用户返回结论和可验证证据。例如，多步计算可以先列出变量和关系，再用计算器核对结果，比直接猜结论更容易验证。但中间步骤也可能是合理化解释，流畅的推理链不能证明答案真实。任务可用可执行代码、检索证据或检查表提高可靠性，而不是要求每个问题都输出很长的分析。对用户展示简短依据和验证结果通常更实用，效果应通过正确率、延迟及 Token 成本的对照实验衡量。
- 评分要点：分解带来的收益、成本、可靠性和隐私边界。

## L018｜大模型为什么会出现幻觉？怎么缓解？

- 知识点：模型幻觉
- 难度：中等
- 参考答案：模型目标是生成高概率文本而非验证事实，训练数据缺失或冲突、问题歧义、上下文噪声和高随机性都可能导致幻觉。缓解方法包括RAG或工具获取证据、限定回答范围、低温生成、信息不足时拒答、结构校验、引用核验和人工审核。高风险任务不能只依赖模型自我反思。例如，要求引用一篇不存在的论文时，模型可能根据常见论文命名方式生成看似可信的标题。即使温度为零，概率最高的输出也可能不符合事实，所以低温只减少随机性。应区分事实错误、违反给定材料和错误解释工具结果，分别通过证据查询、约束与确定性核验处理。评测要包含不可回答问题和引用真实性，统计误答与拒答，不能只观察答复是否自信、完整。
- 评分要点：原因覆盖训练、输入和解码；治理覆盖证据、拒答和验证。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/hallucination.html)

## L019｜MoE 混合专家模型是什么？DeepSeek V3、Qwen 为什么用 MoE？

- 知识点：MoE
- 前置知识：Transformer
- 难度：进阶
- 参考答案：MoE在每层设置多个专家网络，由路由器为每个Token选择少数专家计算，因此总参数可以很大而单Token激活参数较少，提升容量与计算效率。代价是路由负载不均、专家通信、训练稳定性和部署复杂度。采用MoE通常是为了在可控推理成本下扩大模型容量，而非完全免费地增加能力。典型做法是将部分 FFN 换成多个专家，路由器为每个 Token 选择少量专家，注意力等其他模块可能仍是共享的。专家是可训练的网络参数，并不天然对应一个具有人格的 Agent，也不等于多 Agent 协作。总参数与激活参数不同，但部署仍需要存放或分发大量专家权重，跨设备通信可能成为瓶颈。不是所有 Qwen 型号都使用 MoE，讨论优势必须限定具体架构与实际硬件条件。
- 评分要点：稀疏激活、路由、容量收益和系统代价。

## L020｜大模型部署有哪些主流方案？vLLM、TGI、llama.cpp、SGLang 实际项目里怎么选？

- 难度：进阶

## L021｜大模型能力评测指标有哪些？

- 知识点：模型评测
- 难度：中等
- 参考答案：大模型评测需要区分模型能力与业务效果。知识类可参考 MMLU/MMLU-Pro，代码类可参考 HumanEval 或 SWE-bench Verified，数学与科学推理需要各自合适的任务集。但公开 Benchmark 只能作为选型起点，可能受到数据污染、评分方式与业务分布差异影响；最终应从真实请求与失败样本构建经过标注的业务测试集，定期回归。公开测试可区分知识、代码、数学与科学推理，GPQA 更偏高难度科学问答，不能笼统归为数学。业务集应包含正常、缺信息、错误输入、多轮和不可回答样本，保留固定留出集并持续补充失败案例。结构化任务测格式与参数，Agent 任务还要验证实际动作和外部结果。模型裁判需人工校准，报告应同时给出质量、安全、费用和延迟，并防止只针对已知测试集调优。
- 评分要点：区分知识、代码、数学与科学任务；认识榜单局限；设计业务留出集并兼顾安全、费用和延迟。

- 知识点：模型选型
- 难度：中等

## L023｜为什么长上下文会出现 Lost in the Middle？上下文窗口越大越好吗？

- 知识点：长上下文
- 前置知识：Transformer
- 难度：进阶
- 参考答案：模型对上下文不同位置的利用不均，常更关注开头和结尾，中间证据可能因位置偏差、注意力稀释和训练分布不足被忽略。更大窗口只能表示“放得下”，不代表能稳定使用，还会增加预填充延迟和成本。可通过检索筛选、重排、分层摘要和把关键证据靠近问题缓解，并用不同位置的针测试和真实长文问答评测。可以把相同证据分别放在开头、中间和末尾，逐步增加无关文本，比较正确率和引用准确性；还要测试跨段关联，不能只用找一个关键词的针测试代替真实任务。改善手段包括检索筛选、分层摘要、相关证据重排与清晰分区，但不能把重复灌入大量信息当作通用解法。更大窗口有时能减少检索遗漏，也会增加处理与维护成本，选择应依据有效上下文表现而不是输入上限。
- 评分要点：有效上下文与标称窗口区分；原因、成本、缓解和评测。
- 参考资料：[小林面试笔记题解](https://xiaolinnote.com/ai/llm/23_long_context_lost_middle.html)
