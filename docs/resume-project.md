# IPilot：基于 Agent 与混合 RAG 的智能面试学习平台

**技术栈：**Python、FastAPI、Chroma、BM25、RRF、ONNX Cross Encoder

**项目简介：**面向技术面试练习与复盘，开发集在线题库、模拟面试、知识库问答及短板练习推荐于一体的 Web 平台，形成“出题—追问—评分—复盘”练习闭环。

- **混合 RAG：**针对题内检索片段缺少完整参考上下文的问题，设计“题内子块检索＋完整父题返回”结构，融合 BM25、向量召回与 RRF；混合基线在 **37 条可回答测试查询、3 轮评测**中，目标来源 **Recall@3 为100%、MRR 为0.9775**。
- **面试流程编排：**设计持久化面试状态机，根据回答进行定向追问、难度调整与知识点切换，通过阶段、轮次及前置知识约束控制流程，支持中断恢复、提前结束和报告生成，串联连续面试与短板练习推荐。
- **逐点评分与复盘：**结合首次作答和追问补充，按评分要点输出掌握状态、理由及原文证据；校验回答编号与连续原文，将无效证据标为待核验，使评价依据可核对、知识缺口可定位。
- **题库更新可靠性：**实现在线编辑及辅助元信息生成，通过固定题号、请求去重、版本冲突检测和索引/文件发布失败恢复，防止重复保存与旧稿覆盖，维护题库和检索索引的一致性；项目已有 **151 项自动化回归测试全部通过**，覆盖流程约束与更新失败恢复等场景。
- **对照评测与性能分析：**构建 **120 条人工复核评测查询**，按关联主题划分80开发/40测试，完成三轮开发选型与独立验证，保存 **960 条检索结果**；在测试集来源Recall@3均为100%时，混合基线平均检索耗时较MQE/HyDE扩展方案低 **80.3%（5.14秒对26.09秒）**，量化组件收益与开销。

项目时间、角色和姓名按实际情况填写。以上五条可按版面删减；逐点评分保留功能与证据校验描述。

## 数字出处与面试说明

- 120 条检索标注、24 条评分标注由项目作者复核；不是双人盲审。
- 逐点评分条目只介绍功能。评分一致率实验及分歧保留在原始报告中，不作为简历中的准确率亮点。
- 37条为独立的可回答测试问题，三轮共111次观测；另3条无资料测试问题不进入来源召回分母。
- 960 = 开发 80×3 方案×3 轮 + 测试 40×2 方案×3 轮。重复轮次不增加独立问题数。
- 测试集 37 条可回答问题的目标来源 Recall@3，混合基线与组合扩展方案均为 1.0000；没有测试集召回提升证据。无资料的 3 条不进入来源召回分母。
- Recall@3 使用各子问题 Top 3 的目标来源合并命中；复合题的 MRR 取各子问题中最佳目标来源倒数排名。它们不等同于整条复合问题只返回三项的全局排名指标。
- 扩展使测试集 MRR 由 0.9775 变为 1.0000，但差值置信区间含 0；平均检索流程耗时由 5.143 秒增至 26.094 秒。这是三进程评测负载下的检索耗时，不是问答时延。
- 80.3% = (26.094 - 5.143) / 26.094。它是同一测试集两种方案的平均检索耗时比较，未将网页默认配置切换后的收益作为已测成果，也不代表完整问答响应耗时降低80.3%。
- 151项来自现有项目回归报告，失败、错误和跳过均为0；验证的是本地程序行为与异常分支。报告日期为2026-10-12，本次仅重写简历，没有重新运行整套测试或外部API评测。
- 实现了七种可选检索方案；正式开发选型比较三种，测试比较两种，不能说七种都做了全规模实验。
- 40条正式问答已取得有效自动评审，但评审与生成默认同模型，且参考要点部分为完整段落。自动事实支持比例、覆盖F1等不写成“人工答案准确率”；首轮失败与恢复记录均保留。
